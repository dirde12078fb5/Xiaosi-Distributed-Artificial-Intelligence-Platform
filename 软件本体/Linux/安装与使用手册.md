### 1.4 运行原理

- 程序是**单文件 Python 源码**（`/opt/xiaosi/app/xiaosi-app.py`），由系统 `python3` 直接解释执行，没有独立二进制，因此不存在 glibc / 架构兼容问题
- 界面使用 **Tkinter**（Python 标准 GUI），图表与卡片使用 **Pillow** 绘制，系统数据采集使用 **psutil**
- 无常驻服务、无后台守护进程；关闭窗口即退出
- 网络服务（P2P / HTTP / HTTPS / FTP）**默认全部未启动**，只有手动点击「启动」才会监听端口
- GPU 数据优先读 `pynvml`（若安装），否则调用驱动自带的 `nvidia-smi` 命令

## 二、系统要求

### 2.1 操作系统与桌面

| 项 | 要求 |
|---|---|
| 发行版 | Fedora 30+ / RHEL 8+ / Rocky 8+ / Alma 8+ / openSUSE Leap 15+ / Ubuntu 20.04+ / Debian 11+ |
| Python | ≥ 3.7（推荐 3.9+）。RHEL/CentOS 8 默认 `python3` 是 3.6，需启用 `python39` 模块流或改用 `python3.9` 运行 |
| rpm 版本 | ≥ 4.12（低于此版本无法解压 zstd payload，典型为 CentOS 7） |
| 桌面环境 | 需要 X11 或 Wayland 图形会话（GNOME / KDE / XFCE 均可） |
| 无图形环境 | 服务器 / 纯 SSH 下只能使用 CLI 子命令，GUI 会因缺少 `$DISPLAY` 无法启动 |

### 2.2 Python 依赖

| 模块 | 用途 | Fedora | RHEL / Rocky / Alma / CentOS | Debian / Ubuntu | openSUSE | 必需 |
|---|---|---|---|---|---|---|
| `python3` | 运行时 | `python3` | `python3` | `python3` | `python3` | 是 |
| `tkinter` | 图形界面 | `python3-tkinter` | `python3-tkinter` | `python3-tk` | `python3-tk` | 是（GUI） |
| `PIL`（Pillow） | 图表、卡片渲染 | `python3-pillow` | **`python3-pillow`（EPEL）**<br>`python3-pillow-tk`（EPEL，可选） | `python3-pil`<br>`python3-pil.imagetk` | `python3-pillow` | 是 |
| `psutil` | 系统数据采集 | `python3-psutil` | `python3-psutil` | `python3-psutil` | `python3-psutil` | 是 |
| `pynvml`（可选） | 高性能 GPU 采集 | `python3-pynvml` 或 `pip install pynvml` | 同左 | 同左 | 同左 | 否 |

> RPM 元数据：`Requires: python3, python3-psutil`；`Recommends: python3-tkinter, python3-pillow`。
> 用 `dnf install ./包名.rpm` 安装时，Recommends 会被自动带出；用 `rpm -ivh` 不会安装依赖。
>
> **注意**：RHEL / Rocky / Alma / CentOS 的**基础仓库没有 Pillow**，`python3-pillow` 来自 **EPEL**。
> 先 `sudo dnf install -y epel-release` 再装，否则会报 `No match for argument: python3-pillow`。

### 2.3 中文字体

界面中文依赖系统 CJK 字体，**缺失会显示为方块**。注意各发行版**包名不同**：

| 发行版 | 字体包名 | 安装命令 |
|---|---|---|
| Fedora | `google-noto-sans-cjk-fonts` | `sudo dnf install -y google-noto-sans-cjk-fonts` |
| RHEL 9 / Rocky 9 / Alma 9 / CentOS Stream 9 | `google-noto-sans-cjk-ttc-fonts` | `sudo dnf install -y google-noto-sans-cjk-ttc-fonts` |
| RHEL 8 / Rocky 8 / Alma 8 / CentOS 8 | `google-noto-sans-cjk-ttc-fonts`（或 `wqy-microhei-fonts`） | `sudo dnf install -y google-noto-sans-cjk-ttc-fonts` |
| CentOS 7 | `wqy-microhei-fonts` / `wqy-zenhei-fonts`（EPEL） | `sudo yum install -y epel-release wqy-microhei-fonts` |
| Debian / Ubuntu | `fonts-noto-cjk` | `sudo apt install -y fonts-noto-cjk` |
| openSUSE | `noto-sans-cjk-fonts` | `sudo zypper install -y noto-sans-cjk-fonts` |

> **重点**：Fedora 的包名是 `google-noto-sans-cjk-fonts`，而 **RHEL / Rocky / Alma / CentOS 的包名带 `-ttc-`**：`google-noto-sans-cjk-ttc-fonts`。
> 在 RHEL 系上直接照抄 Fedora 的包名会报 `No match for argument: google-noto-sans-cjk-fonts`。
>
> 不确定本机用哪个包名时，先查一下：
>
> ```bash
> dnf search cjk
> dnf provides '*/NotoSansCJK-Regular.ttc'
> rpm -qa | grep -iE 'noto|cjk|wqy'
> ```

装完执行 `fc-cache -f` 并重启应用即可。验证：`fc-list :lang=zh | wc -l` 大于 0。

| 项 | 说明 |

| 监控 | 需要 NVIDIA 官方驱动，`nvidia-smi` 可执行即可（安装方法见 [8.4](#84-安装-nvidia-驱动获取-nvidia-smi)） |

### 2.5 权限说明

- **安装**需要 root（写入 `/opt`、`/usr/bin`、`/usr/share`）
- **日常运行建议普通用户**，配置与日志写入 `~/.config/xiaosi`
- 不要用 `sudo xiaosi` 长期运行，否则配置会落在 `/root/.config/xiaosi`，且 GUI 可能无法连接到当前用户会话

## 三、安装

### 3.1 获取与校验安装包

```bash
# 查看包信息
rpm -qip xiaosi-ai-platform-5.26.11.29-3.noarch.rpm

# 校验完整性（与发布方提供的 SHA256 比对）
sha256sum xiaosi-ai-platform-5.26.11.29-3.noarch.rpm

# 查看包内文件数量（应为 3512）
rpm -qlp xiaosi-ai-platform-5.26.11.29-3.noarch.rpm | wc -l
```

> 当前包**未做 GPG 签名**，请从可信渠道获取并核对 `sha256sum`。

### 3.2 Fedora / RHEL / Rocky / AlmaLinux

```bash
# 1) 运行时依赖：Tkinter + psutil（基础仓库即可）
sudo dnf install -y python3 python3-tkinter python3-psutil

# 2) Pillow 来自 EPEL（RHEL 基础仓库没有）
sudo dnf install -y epel-release
sudo dnf install -y python3-pillow python3-pillow-tk

# 3) 中文字体（包名随发行版不同，二选一）
sudo dnf install -y google-noto-sans-cjk-ttc-fonts      # RHEL 9 / Rocky 9 / Alma 9 / CentOS Stream 9
# sudo dnf install -y google-noto-sans-cjk-fonts        # Fedora 用这个
# 若都提示 No match：sudo dnf search cjk 查本机可用包名

# 4) 安装（必须带 ./ 表示本地文件，dnf 会解析依赖）
sudo dnf install -y ./xiaosi-ai-platform-5.26.11.29-3.noarch.rpm

# 5) 验证
rpm -q xiaosi-ai-platform
xiaosi version
```

> **Fedora 用户**：Pillow 在基础仓库，不需要 EPEL，第 1、2 步可合并为
> `sudo dnf install -y python3 python3-tkinter python3-pillow python3-psutil`。

期望输出：

```text
xiaosi-ai-platform-5.26.11.29-3.noarch
小思分布式人工智能™ 多功能平台 12 Ultra X3D
XiaoSi Distributed AI™ Multi-Function Platform 12 Ultra X3D
GEN 架构版本 / GEN version: 5.26.11.29
```

> RHEL/CentOS 8 的默认 `python3` 是 3.6，程序依赖 `dataclasses`（3.7+）会导入失败。先启用新版：
> `sudo dnf module enable -y python39 && sudo dnf install -y python39`，之后用
> `python3.9 /opt/xiaosi/app/xiaosi-app.py` 启动（或把 `/usr/bin/xiaosi` 末行的 `python3` 改成 `python3.9`）。
> RHEL 9 / Rocky 9 / Alma 9 及以上默认 3.9，无需处理。

### 3.3 openSUSE

```bash
sudo zypper install -y python3 python3-tk python3-pillow python3-psutil noto-sans-cjk-fonts
sudo zypper install ./xiaosi-ai-platform-5.26.11.29-3.noarch.rpm
xiaosi version
```

> openSUSE 的 Tkinter 包名是 `python3-tk`，Pillow 是 `python3-pillow`。

### 3.4 Ubuntu / Debian

系统没有 RPM 包管理，三种方式任选。

**方式 A：转成 deb（推荐，便于 apt 管理）**

```bash
sudo apt install -y alien
sudo alien -d --scripts xiaosi-ai-platform-5.26.11.29-3.noarch.rpm
sudo apt install -y python3 python3-tk python3-pil python3-pil.imagetk python3-psutil fonts-noto-cjk
sudo dpkg -i xiaosi-ai-platform_5.26.11.29-3_all.deb
xiaosi version
```

**方式 B：直接用 rpm 安装**

```bash
sudo apt install -y rpm python3-tk python3-pil python3-pil.imagetk python3-psutil fonts-noto-cjk
sudo rpm -ivh --nodeps xiaosi-ai-platform-5.26.11.29-3.noarch.rpm
xiaosi version
```

> `--nodeps` 是因为 Debian 的 rpm 数据库里没有 apt 包名映射；Python 依赖已在上一条命令装好。

**方式 C：不安装，直接跑源码**

```bash
sudo apt install -y python3-tk python3-pil python3-pil.imagetk python3-psutil fonts-noto-cjk
python3 "/你的路径/xiaosi-app.py"
```

### 3.5 WSL（Windows Subsystem for Linux）

```bash
sudo apt install -y rpm python3-tk python3-pil python3-pil.imagetk python3-psutil fonts-noto-cjk
sudo rpm -ivh --nodeps /mnt/d/Xian_Mu_Kai_FA/小思分布式人工智能系类/release/Linux/xiaosi-ai-platform-5.26.11.29-3.noarch.rpm
```

WSLg 会把窗口直接显示到 Windows 桌面（Win10 需 21H2+ 并启用 WSLg）。

### 3.6 离线 / 内网安装

目标机无法联网时，先在**相同发行版版本**的联网机器上下载依赖：

```bash
# 联网机器：下载 rpm 及其依赖到本地目录
# RHEL/Rocky/Alma：先装 epel-release，再下载（Pillow 只在 EPEL；字体包名带 -ttc-）
sudo dnf install -y epel-release
dnf download --resolve --alldeps --destdir ./deps \
    python3-tkinter python3-psutil python3-pillow python3-pillow-tk \
    google-noto-sans-cjk-ttc-fonts
# 拷贝 deps/ 与安装包到目标机后
sudo dnf install -y ./deps/*.rpm ./xiaosi-ai-platform-5.26.11.29-3.noarch.rpm
```

### 3.7 升级、重装与回滚

```bash
# 升级到新版本（保留配置）
sudo dnf upgrade -y ./xiaosi-ai-platform-<新版本>.noarch.rpm

# 强制重装当前版本（修复文件丢失）
sudo rpm -Uvh --replacepkgs --nodeps ./xiaosi-ai-platform-5.26.11.29-3.noarch.rpm

# 回滚到旧版本包
sudo dnf downgrade -y ./xiaosi-ai-platform-<旧版本>.noarch.rpm
# 或
sudo rpm -Uvh --oldpackage --nodeps ./xiaosi-ai-platform-<旧版本>.noarch.rpm
```

> 配置文件在用户目录，升级/重装不会覆盖；主题、语言等设置会保留。

## 四、启动与退出

### 4.1 启动方式

| 方式 | 操作 |
|---|---|
| 命令 | `xiaosi`（等同 `xiaosi gui`） |
| 桌面菜单 | 应用菜单搜索「小思」或「XiaoSi」 |
| 文本界面 | `xiaosi tui`（无图形环境 / GUI 崩溃时使用） |
| 指定语言 | `xiaosi --lang zh` / `xiaosi --lang en` |
| 源码运行 | `python3 /opt/xiaosi/app/xiaosi-app.py` |

> `xiaosi gui` 异常退出时，若当前是交互终端，启动器会**自动进入 ASCII 界面**并提示原因。

### 4.2 首次启动做了什么

1. 创建配置目录 `~/.config/xiaosi/`（已存在则复用）
2. 初始化日志 `xiaosi-日志.log` 与审计数据库 `xiaosi_cache.db`
3. 探测硬件：CPU 型号/核心数、内存、磁盘、网卡
4. 探测 GPU：`nvidia-smi` 是否存在、能否读取显卡
5. 构建首屏「硬件检测」页；其余页面**首次进入时才构建**（懒加载，加快启动）

首次启动比后续略慢，属正常现象。

### 4.3 启动参数

| 参数 | 说明 |
|---|---|
| `--lang zh` | 中文界面（覆盖环境变量与配置） |
| `--lang en` | 英文界面 |
| `-h` / `--help` | 打印 CLI 帮助后退出 |
| `-V` / `--version` | 打印版本号后退出 |
| 子命令 | 见[第六章](#六命令行参考) |

### 4.4 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `XIAOSI_LOG_DIR` | `$XDG_CONFIG_HOME/xiaosi` 或 `~/.config/xiaosi` | 日志、配置缓存、审计数据库目录 |
| `XIAOSI_LANG` | 由系统 locale 推断 | `zh` 或 `en`，优先级低于 `--lang` |
| `DISPLAY` / `WAYLAND_DISPLAY` | 由桌面会话设置 | GUI 必需 |

### 4.5 退出

- 点击窗口关闭按钮，或终端里 `Ctrl+C`
- 退出时会保存配置缓存（主题、语言、路径、渲染后端）
- 程序不会驻留后台；若使用了网络服务，退出即停止监听

### 4.6 开机自启（可选）

```bash
mkdir -p ~/.config/autostart
cp /usr/share/applications/xiaosi.desktop ~/.config/autostart/
# 若不想每次登录都弹窗，可加一行隐藏参数（自启不推荐，按需使用）
```

删除 `~/.config/autostart/xiaosi.desktop` 即取消自启。

## 七、语言与本地化

### 7.1 语言优先级

从高到低：

1. 命令行参数 `--lang zh|en`
2. 环境变量 `XIAOSI_LANG=zh|en`
3. 配置文件 `~/.config/xiaosi/config_cache.json` 的 `"language"`
4. 系统 locale：`LANG`/`LC_ALL` 以 `zh` 开头用中文，否则英文

### 7.2 三种切换方式

```bash
# 方式 1：单次启动指定
xiaosi --lang en

# 方式 2：当前 shell 会话
export XIAOSI_LANG=zh
xiaosi

# 方式 3：图形界面 系统设置 → 语言 → 中文/English（保存后重启生效）
```

### 7.3 双语输出规则

- **GUI**：整个界面（侧边栏、页面标题、卡片、按钮、图表占位、状态栏、对话框、窗口标题）随语言切换
- **CLI**：始终输出「中文 / English」双语对齐格式，与语言设置无关，便于跨 locale 阅读与脚本解析
- 用户数据（文件路径、进程名、GPU 型号、日志内容）不做翻译

### 7.4 说明

内置仅 `zh`、`en` 两种语言资源。新增语言需修改源码中的 `I18N_SEGMENTS` 字典与 `I18n.TRANSLATIONS`。

## 八、GPU 与渲染加速

### 8.1 采集链路

```text
pynvml（nvidia-ml-py） ──可用──▶ 读取利用率/显存/温度/进程
        │不可用
        ▼
nvidia-smi 命令解析 ──可用──▶ 读取利用率/显存/温度
        │不可用
        ▼
显示"未检测到 NVIDIA 显卡"，其它功能不受影响
```

- 驱动安装：见 [8.4 安装 NVIDIA 驱动](#84-安装-nvidia-驱动获取-nvidia-smi)
- 验证：`nvidia-smi` 能正常输出即满足监控条件
- `pynvml` 可选：`pip install pynvml`（或 `nvidia-ml-py`），装后采集更快更稳

### 8.2 渲染后端（系统设置 → 界面渲染加速）

| 选项 | 说明 |
|---|---|
| 自动 | 有可用 CUDA 时用原生内核，否则回退 CPU |
| 原生 CUDA 内核 | 驱动级 PTX，最快；需要 NVIDIA 驱动与 GPU |
| 兼容模式 | 纯 CPU 渲染，适用于无独显或驱动异常环境 |

选择后点「保存设置」立即应用。同页可点「渲染性能」查看当前后端与单卡耗时对比。

### 8.3 无独显环境

- GPU 卡片与硬件页显示「未检测到 NVIDIA 显卡」（附安装/更新驱动提示）
- 渲染自动走 CPU，图表功能不受影响
- 其它页面（网络、文件、开发工具等）完全可用

### 8.4 安装 NVIDIA 驱动（获取 nvidia-smi）

> `nvidia-smi` **不是独立软件**，它随 NVIDIA 闭源驱动一起安装。驱动装好并重启后，`nvidia-smi` 自动出现在 `/usr/bin/nvidia-smi`。
> 只做 GPU 监控不需要装 CUDA Toolkit，装驱动即可。

#### 8.4.1 RHEL 9 / Rocky 9 / Alma 9（NVIDIA 官方 CUDA 源）

```bash
# 1. 添加 NVIDIA CUDA 仓库（RHEL 8 把 rhel9 换成 rhel8）
sudo dnf config-manager --add-repo \
  https://developer.download.nvidia.com/compute/cuda/repos/rhel9/x86_64/cuda-rhel9.repo
sudo dnf clean all

# 2. 安装 DKMS 版驱动（内核升级后自动重编）
sudo dnf -y module install nvidia-driver:latest-dkms
sudo dnf -y install cuda-drivers

# 3. 重启并验证
sudo reboot
nvidia-smi
```

**备选：ELRepo（只要驱动、不要 CUDA，体积更小）**

```bash
sudo dnf install -y https://www.elrepo.org/elrepo-release-9.el9.elrepo.noarch.rpm
sudo dnf install -y kmod-nvidia
sudo reboot
nvidia-smi
```

CentOS 7 用 `elrepo-release-7.el7.elrepo.noarch.rpm` + `kmod-nvidia`。

#### 8.4.2 Fedora（RPM Fusion）

```bash
sudo dnf install -y \
  https://mirrors.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm \
  https://mirrors.rpmfusion.org/nonfree/fedora/rpmfusion-nonfree-release-$(rpm -E %fedora).noarch.rpm
sudo dnf install -y akmod-nvidia xorg-x11-drv-nvidia-cuda
sudo reboot

```

#### 8.4.6 WSL2 / 容器

| 环境 | 做法 |
|---|---|
| WSL2 | **驱动装在 Windows 侧**，不要在 WSL 内装。WSL 自带 `/usr/lib/wsl/lib/nvidia-smi`，直接 `nvidia-smi` 或 `/usr/lib/wsl/lib/nvidia-smi` 调用 |
| Docker | 宿主机装驱动 + `nvidia-container-toolkit`，容器用 `--gpus all` 启动，容器内即可见 `nvidia-smi` |
| 云主机 | 选择带 GPU 的实例镜像，厂商镜像通常已预装驱动 |

#### 8.4.7 Secure Boot 与内核升级

- **开启 Secure Boot** 时，第三方内核模块必须签名并完成 MOK 注册，否则拒绝加载（`nvidia-smi` 报 `NVIDIA-SMI has failed because it couldn't communicate with the NVIDIA driver`）
- MOK 注册：安装过程中会提示设置一次性密码，重启后在蓝色 MOK 界面选择 Enroll MOK；也可手动导入
  （Ubuntu 通常在 `/var/lib/shim-signed/mok/MOK.der`，Fedora akmods 在 `/etc/pki/akmods/certs/`）
- **内核升级后**：`akmod-nvidia`（Fedora）、`nvidia-driver:latest-dkms`（RHEL 系）、`nvidia-driver`（Debian/Ubuntu）会自动重编；ELRepo 的 `kmod-nvidia` 跟随仓库更新，重启前建议先确认新内核已有对应模块
- 实在无法签名时，可在 BIOS 关闭 Secure Boot（仅建议测试环境）

#### 8.4.8 验证与卸载

```bash
nvidia-smi                 # 驱动版本、GPU 型号、显存、进程
lsmod | grep nvidia        # 模块是否加载
modinfo nvidia | head -5   # 模块版本
```

卸载：

```bash
# RHEL 系（CUDA 源安装）
sudo dnf module remove --all nvidia-driver
# ELRepo
```

## 十二、故障排除

### 12.1 快速定位表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: No module named 'tkinter'` | 未装 Tkinter | 见 12.2 |
| `ModuleNotFoundError: No module named 'PIL'` | 未装 Pillow | 见 12.3 |
| `ModuleNotFoundError: No module named 'psutil'` | 未装 psutil | `dnf install python3-psutil` |
| 启动器打印「缺少运行所需组件」 | 依赖预检拦截 | 按提示命令安装后重试 |
| `No match for argument: google-noto-sans-cjk-fonts` | 发行版包名不同（RHEL 系带 `-ttc-`） | 见 12.4.1 |
| `No match for argument: python3-pillow` | RHEL 系基础仓库无 Pillow，需 EPEL | 见 12.3 |
| `X Error: BadLength (RenderAddGlyphs)` 启动即崩 | Tk 8.6 + 彩色 emoji 字体已知缺陷 | 见 12.11 |
| 中文显示方块 | 无 CJK 字体 | 见 12.4 |
| 界面全英文 | 语言判定为英文 | 见 12.5 |
| `Unknown payload compression` / `rpmlib(PayloadIsZstd)` | rpm 版本过旧 | 见 12.6 |
| `couldn't connect to display` | 无图形会话 | 见 12.7 |
| GPU 页显示「未检测到」 | 无驱动/无显卡 | 见 12.8 |
| `nvidia-smi: command not found` | 未安装 NVIDIA 驱动 | 见 8.4 |
| 启动很慢 | 首次启动建缓存、字体扫描 | 见 13 |
| 每次启动都提示字体/图标 WARNING | 正常提示，不影响使用 | 可忽略 |

### 12.2 缺少 Tkinter

```bash
sudo dnf install -y python3-tkinter      # Fedora / RHEL 8+ / Rocky / Alma / CentOS Stream
sudo apt install -y python3-tk           # Debian / Ubuntu
sudo zypper install -y python3-tk        # openSUSE
```

CentOS 7 需要 EPEL：

```bash
sudo yum install -y epel-release
sudo yum install -y python3-tkinter python3-pillow python3-psutil
```

### 12.3 缺少 Pillow / `No match for argument: python3-pillow`

```bash
# Fedora（Pillow 在基础仓库）
sudo dnf install -y python3-pillow
# Debian / Ubuntu
sudo apt install -y python3-pil python3-pil.imagetk
# openSUSE
sudo zypper install -y python3-pillow
```

**RHEL / Rocky / Alma / CentOS 基础仓库不含 Pillow**，必须启用 EPEL：

```bash
sudo dnf install -y epel-release
sudo dnf install -y python3-pillow python3-pillow-tk
```

- `python3-pillow-tk` 提供 `PIL.ImageTk`（界面贴图用），不装也能启动，只是图表改用纯 Tk 绘制，清晰度略降
- 企业内网无法使用 EPEL 时，用 pip 装到系统或用户目录：

```bash

# python3 -m pip install --user --break-system-packages pillow
```

```bash
python3 -c "from PIL import ImageTk; print('ImageTk OK')"
```

### 12.4 中文显示为方块

```bash
fc-list :lang=zh | wc -l        # 结果为 0 说明没装中文字体

# 按发行版装（注意 RHEL 系包名带 -ttc-）
sudo dnf install -y google-noto-sans-cjk-ttc-fonts      # RHEL / Rocky / Alma / CentOS 8-9
sudo dnf install -y google-noto-sans-cjk-fonts          # Fedora
sudo apt install -y fonts-noto-cjk                      # Debian / Ubuntu
sudo zypper install -y noto-sans-cjk-fonts              # openSUSE

fc-cache -f
fc-list :lang=zh | wc -l        # 复查，应大于 0
```

装完重新启动 `xiaosi`。

#### 12.4.1 `No match for argument: google-noto-sans-cjk-fonts`

**原因**：包名写的是 Fedora 版本。RHEL / Rocky / Alma / CentOS 的中文字体包叫
`google-noto-sans-cjk-ttc-fonts`（多了 `-ttc-`）。

**解决**：

```bash
sudo dnf install -y google-noto-sans-cjk-ttc-fonts
```

如果仍提示 No match（精简镜像 / 未启用 AppStream / 离线环境），按下面顺序排查：

```bash
# 1. 查本机仓库里到底有哪些 CJK 字体
dnf search cjk
dnf provides '*/NotoSansCJK-Regular.ttc'

# 2. 备选：文泉驿字体（体积小，覆盖常用简体）
sudo dnf install -y wqy-microhei-fonts
# 或
sudo dnf install -y wqy-zenhei-fonts

# 3. 备选：安装中文语言包，会连带拉取默认中文字体
sudo dnf install -y langpacks-zh_CN
```

**离线环境**：从任意有字体包的机器复制 `.ttc` / `.ttf` 过去即可，不需要装 rpm：

```bash
# 目标机
mkdir -p ~/.local/share/fonts
# 把 NotoSansCJK-Regular.ttc 等复制到该目录
fc-cache -f
fc-list :lang=zh | head
```

字体文件位置参考：`/usr/share/fonts/google-noto-sans-cjk-ttc-fonts/`、
`/usr/share/fonts/wqy-microhei/`。

> 只有中文显示受影响，英文界面与 CLI 子命令不受字体缺失影响。

或图形界面 系统设置 → 语言 → 中文 → 保存 → 重启。

### 12.6 rpm 版本过旧

`Unknown payload compression` / `rpmlib(PayloadIsZstd)` 说明系统 rpm 不支持 zstd（典型 CentOS 7）。

- 升级到 Rocky/Alma/RHEL 8+ 等新发行版
- 或不用 RPM，直接跑源码：

```bash
sudo yum install -y python3 python3-tkinter python3-pillow python3-psutil
python3 /opt/xiaosi/app/xiaosi-app.py
```

### 12.7 无图形环境 / 无法连接显示

```bash

xiaosi cpu-ls            # CLI 子命令仍可用
```

需要 GUI 时：本地图形登录、`ssh -X` 转发、VNC 或 WSLg。

### 12.8 GPU 未检测到

```bash
nvidia-smi                        # 能输出即驱动正常
which nvidia-smi
lsmod | grep nvidia
```

- 驱动未装：`nvidia-smi: command not found` 说明没装驱动，见 [8.4 安装 NVIDIA 驱动](#84-安装-nvidia-驱动获取-nvidia-smi)
- 驱动装了但 `nvidia-smi` 报 `couldn't communicate with the NVIDIA driver`：多为 Secure Boot 未完成 MOK 注册、或内核升级后模块未重编，见 8.4.7
- 容器/WSL：需正确透传 GPU（WSL2 驱动装在 Windows 侧）
- 双显卡笔记本：确认独显未被 BIOS 禁用；Ubuntu 可 `prime-select nvidia`
- 驱动已装仍显示「未检测到」：重启后确认 `lsmod | grep nvidia` 有输出

### 12.9 多开与单实例

Linux 版**不限制多开**。多开时多个窗口共用同一 `~/.config/xiaosi`（日志会并写），建议只开一个；若需并行，给每个实例指定独立目录：

```bash
XIAOSI_LOG_DIR=~/.config/xiaosi-2 xiaosi
```

### 12.10 权限相关

- `Permission denied` 写日志：目录不可写。设 `XIAOSI_LOG_DIR` 到可写目录
- 用 `sudo xiaosi` 看不到界面：root 无权访问当前用户 X 会话。请用普通用户运行

### 12.11 启动崩溃：`X Error: BadLength (RenderAddGlyphs)`

完整报错形如：

```text
X Error of failed request:  BadLength (poly request too large or internal Xlib length error)
  Major opcode of failed request:  139 (RENDER)
  Minor opcode of failed request:  20 (RenderAddGlyphs)
```

**原因**：这是 **Tk 8.6 / Xft 的已知缺陷**，不是本软件的业务错误。以下两类字体都可能触发：

1. **彩色 emoji 字体**（Noto Color Emoji 等）+ astral 平面 emoji（U+1F000 以上，如 💾📊🌐）
   参考：Red Hat Bug #2031108、Python Issue #42225
2. **超大字形集的 CJK 字体**（如 `google-noto-sans-cjk-ttc-fonts`，单字体约 6.5 万字形）
   Tk 一次性请求字形时超过 X11 单请求上限，同样报 `BadLength`

> 判断方法：把窗口标题栏/界面语言换成英文（`xiaosi --lang en`）仍崩、或删掉 emoji 字体仍崩，
> 基本就是第 2 类（CJK 字体）导致的。

**方案 A（推荐）：升级到 5.26.11.29-3 及以上**

该版本在 Linux 显示层统一剥离 emoji（含侧边栏图标、按钮、图表文字、对话框、
Treeview、日志文本与字体宽度测量），从源头避免彩色字形请求；Windows 版界面不变。

```bash
sudo dnf upgrade -y ./xiaosi-ai-platform-5.26.11.29-3.noarch.rpm
```

**方案 B：移除彩色 emoji 字体（保留中文字体）**

```bash
rpm -qa | grep -i emoji
sudo dnf remove -y google-noto-color-emoji-fonts
fc-cache -f
xiaosi
```

只删彩色 emoji 字体即可，**不要**删中文字体。删除后 emoji 会退化为单色或方块，不影响程序运行。

**方案 C：换用字形集较小的 CJK 字体**

若属于第 2 类原因（Noto CJK TTC），换成传统小字形集字体通常即可恢复 GUI：

```bash
sudo dnf remove -y google-noto-sans-cjk-ttc-fonts google-noto-serif-cjk-ttc-fonts
sudo dnf install -y wqy-microhei-fonts
fc-cache -f
xiaosi
```

`wqy-microhei-fonts` 字形集约 3 万，不会触发单请求超限；中文显示正常，只是少数字形风格不同。
如仍要保留 Noto CJK，可只保留 `NotoSansCJK-Regular.ttc` 的单一 SC 面（自行裁剪字体，进阶操作）。

**方案 D：改用 ASCII 文本界面（不依赖图形渲染，必定可用）**

```bash
xiaosi tui        # 或 xiaosi ascii
```

TUI 不创建窗口、不做字体渲染，任何终端都能运行。`xiaosi gui` 异常退出时，
若在交互终端中，启动器也会自动切到 TUI。详见 [6.10](#610-ascii-文本界面xiaosi-tui)。

**验证**

```bash
fc-list | grep -i emoji          # 有输出说明装了彩色 emoji 字体
fc-list :lang=zh | wc -l         # 中文可用字体数，需 > 0
rpm -qa | grep -i cjk            # 查看是否装了 Noto CJK TTC
```

> 该问题与显卡、驱动无关，换 NVIDIA 驱动不会解决。

## 十三、性能与资源占用

| 指标 | 说明 |
|---|---|
| 启动 | 首屏只构建硬件检测页，其余页面首次进入才构建；非首屏页面懒加载 |
| 常驻内存 | 主要是 Python 解释器 + Tkinter + 图表缓存，具体随页面数量增长 |
| CPU | 硬件/监控页每秒采样一次；页面不可见时暂停重绘 |
| 滚动 | 像素级缓动（60 fps 目标），表格逐行平滑；拖动滚动条时暂停动画 |
| 渲染 | 图表按 2× 超采样绘制再降采样（抗锯齿更清晰）；可在设置页切换 CUDA/CPU 后端 |
| 磁盘 | 安装占用约 508 MB（其中 config 资源约 484 MB） |
| 网络 | 仅在手动启动网络服务后监听端口 |

建议配置：2 核 CPU / 4 GB 内存以上；需要 GPU 监控时另备 NVIDIA 显卡与驱动。

## 十四、安全建议

1. **普通用户运行**，仅在安装/卸载时使用 root
2. 网络服务（P2P/HTTP/HTTPS/FTP）**默认关闭**；启用前确认绑定的网卡与端口，用防火墙限制来源
3. FTP 默认账号密码为示例值（`user` / `123456`），启用前务必修改
4. 日志与审计库包含主机名、路径、进程名等系统信息，对外分享前请脱敏
5. 安装包未做 GPG 签名，请核对 `sha256sum` 并从可信渠道获取
6. 开发工具中的 Hash/Base64/JWT 等全部本地计算，不会上传数据
